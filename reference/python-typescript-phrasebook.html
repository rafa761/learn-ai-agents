The Python → TypeScript Phrasebook

Everything you already know in Python, said with a TypeScript accent. Built for a Senior Python developer learning TS by building AI agents.

How to use this

Find the Python idiom you're reaching for; read the TS column; copy the pattern. Do not read it end-to-end — it's a phrasebook, not a chapter. Lessons will link here whenever a new mapping appears.

6 · Narrowing & discriminated unions the agent pattern

This is the one section worth memorising. Agent messages, tool calls, tool results, stream events — every agent SDK in TypeScript models them as a discriminated union: objects sharing a literal tag field (kind), narrowed like isinstance checks in a Python match.

python — match + isinstance
def describe(msg: AgentMessage) -> str:
    match msg:
        case TextMessage(text=t):
            return f"text: {t}"
        case ToolCallMessage(tool=tool):
            return f"call {tool}"
typescript — switch on the tag
function describe(msg: AgentMessage): string {
  switch (msg.kind) {          // the literal tag
    case "text":      return `text: ${msg.text}`;
    case "tool_call": return `call ${msg.tool}`;
  }                            // compiler enforces all cases
}
PythonTypeScriptNotes
isinstance(x, T)x instanceof T (classes) · typeof x === "..." (primitives) · "k" in x (key check)Three narrowing tools where Python has one.
match exhaustivenessswitch + return-type annotationAdd a union member, forget a case → compile error, not a runtime surprise.
assert_never(x)const _exhaustive: never = xThe explicit exhaustiveness guard, same idea in both languages.
TypeGuard / TypeIsx is T predicate: function isToolCall(m: AgentMessage): m is ToolCallMessageUser-defined narrowing — used all over agent SDK internals.

7 · Runtime validation: pydantic → zod

pydantic validates at runtime (parse JSON → typed model or error). TS interfaces vanish at compile time — so for anything crossing a trust boundary (API responses, LLM tool-call arguments), use zod:

python — pydantic
class ToolCall(BaseModel):
    tool: str
    args: dict[str, Any]

call = ToolCall.model_validate(json.loads(raw))
typescript — zod
import { z } from "zod";

const ToolCall = z.object({
  tool: z.string(),
  args: z.record(z.unknown()),
});

const call = ToolCall.parse(JSON.parse(raw));
// call: { tool: string; args: Record<string, unknown> }

zod's parse throws on bad input like pydantic's model_validate; safeParse returns a result object instead of throwing. Bonus: z.infer<typeof ToolCall> derives the static type from the validator — one source of truth.

9 · Mindset shifts (no syntax equivalent)

  • Structural typing everywhere. Any object with the right shape satisfies the interface — no inheritance, no implements required. Ducks, formally.
  • Types are erased. After compilation there is only JavaScript. Anything you need at runtime (validation, schemas) must exist as values — hence zod.
  • Immutability is a convention. const prevents rebinding, not mutation. Reach for readonly and spread ({ ...msg, role: "assistant" } ≈ {**msg, "role": "assistant"}) — agent loops mutate state by creating new messages, never by editing old ones.
  • No GIL, no asyncio event loop management. Concurrency is the platform's problem; you just await.
