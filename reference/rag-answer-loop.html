§1The loop, end to end

offline once (lesson 0004) · online per query (lesson 0005)
OFFLINE   document → chunk → embed → keep vectors + text in memory
ONLINE    query → embed → cosine-rank → top-k → zod seam → grounded prompt → model → cited answer | refusal

Every arrow is code you have typed. Nothing in the online half changes when the corpus grows from four paragraphs to 636 pages except where the vectors live (§5).

§2The grounded prompt (book §16.2.4, translated)

three instructions, one contract
system: "Answer using ONLY the provided context. If the context does not contain
        enough information, say so explicitly — do not fill gaps from your own
        knowledge. Cite your sources using [Doc N] notation."

user:    "Context documents:\n\n[Doc 1] (score 0.541)\n…chunk…\n\n[Doc 2] …\n\nQuestion: …"
InstructionWhy it existsWhat breaks without it
ONLY the contextThe model will answer from weights otherwise — that is its trainingStale or invented facts smuggled beside correct retrievals
Say so if insufficientMakes refusal a correct answer, not a failureFluent hallucination on off-corpus queries
Cite [Doc N]Every claim becomes checkable against a chunkPlausible text you cannot audit

Verified live 2026-09-08: with all three, an on-corpus query cites [Doc 1] [Doc 3]; the off-corpus control (“what do Vogons think of poetry”) refuses honestly. The refusal is the feature working, not the system failing.

§3Why top-k, never a score threshold

A cosine score is not a property of a text. It is a property of a pair (query, chunk), computed by one particular model. Same query tomorrow, same value; different query, different scale entirely. Our two live queries scored 0.54 (great match) and 0.17 (no match) — but a broader query can max out at 0.35 and a narrow one never drops below 0.5. There is no universal “0.4 means relevant” line, so a hardcoded threshold is a bug that works on Tuesdays. The ranking is the dependable part; take the best k and let the generator judge sufficiency — that is exactly what the say-so-if-insufficient instruction is for.

§4The retrieval budget, in arithmetic

what one question costs
prompt ≈ system (~60 tokens) + Σ retrieved chunks + question
chunks ≈ k × tokens-per-chunk          e.g. 3 × ~80 = 240 tokens — trivial
capstone: 10 × ~250 = 2,500 tokens per question — a real line item, so k is a knob

k is the only budget dial visible to the retriever: raise it for recall (more evidence), lower it for cost and focus (less dilution). Chunk size sets it indirectly — double the chunk size and you halve how many chunks fit. This is the constraint your lesson-0004 quiz miss distinguished: it budgets the prompt, it does not shape the chunk.

§5When to graduate from in-memory cosine

Corpus sizeRetrievalCost
≤ ~10k chunks (this course, so far)vectors.map(cosine).sort() in memorymilliseconds, zero infrastructure
beyonda vector store / ANN index (pgvector, sqlite-vec, hosted)an optimization, not a semantic change — same vectors, same cosine, indexed so you don’t scan all of them

The store finds approximate nearest directions without comparing against everything — trading a little recall for a lot of speed. Nothing you learned changes: embed, rank, top-k; only the “rank” step gets an index behind it. The capstone will need this; lesson 0006’s evaluation harness will tell you whether it does.
