The RAG evaluation harness

Golden set → retrieval metrics → citation check → faithfulness judge. The evidence layer that turns “it seems to work” into numbers — and tells you which half broke. Print me.

Built in Lesson 0006. Companions: the grounded-loop cheat sheet (what is being measured) and the chunking cheat sheet (what the gold annotations refer to). Book: Roitman 2026, ch. 16 §16.8 (arXiv:2606.24937).

§1Three levels, three questions

LevelQuestionInstrumentsStability
1 · RetrievalDid the right passages surface — how high?recall@k, precision@k, MRR over a golden setdeterministic (pure function of corpus + model + cache)
2 · GenerationCorrect? Faithful to context? Relevant?citation check (mechanical) · faithfulness judge (semantic) · answer relevancejudge is stochastic — expect ±1 claim across runs
3 · End-to-endDoes the user win?human preference, task success rate, latency-adjusted utilityproduction territory

Debug protocol: when an answer is wrong, climb from the bottom of cost and variance — check level 1 first (free, instant, reproducible), then level 2. The book's §16.8 warning travels with the table: optimizing one level in isolation backfires (max recall via big k ⇒ context full of marginal passages ⇒ generation degrades).

§2The golden set, anatomized

evaluation data is code
interface GoldRow {
  q: string;              // the question a real user might ask
  relevant: number[];     // chunk indices a HUMAN judged relevant — annotation is the irreplaceable step
  expectRefusal?: true;   // negative probe: nothing is relevant; the system wins by refusing
}
RuleWhy
Annotation is human, once, by reading the corpusThe chunker cuts mid-sentence by design — some answers genuinely straddle chunks (our “three limitations” row: gold [0, 1]). Deciding that is judgment, not automation
Multi-gold rows are allowed and welcomeThey turn recall from found/not-found into an honest fraction — half the evidence is half the answer
Keep at least one negative probeA system can score perfectly on answerable questions and still fail the user whose question has no answer (the Vogon row)
The set grows with real useEvery user question that exposes a bug becomes a row — the harness compounds

§3The retrieval metrics, translated

book eq. 16.22–16.24, in plain code
recall@k     = |top-k ∩ gold| / |gold|     // of what's relevant, what share made it? (hit-rate when |gold| = 1)
precision@k  = |top-k ∩ gold| / k          // of what you fed the model, what share was gold? (the over-retrieval tax)
MRR          = mean( 1 / rank-of-first-gold )   // position, not just presence: rank 1 → 1.0, rank 2 → 0.5

Our verified run (lesson 0006, corpus of 4 chunks, 4 scored rows + 1 probe): recall@1 = 0.875 · recall@2 = 1.000 · precision@2 = 0.625 · precision@3 = 0.417 · MRR = 1.000. The story those numbers tell: k=2 finds every gold chunk; k=3 adds no recall and dilutes precision — so the shipped config is k=2, on evidence. Note also the near-tie row (golds at 0.390 / 0.379, both under 0.4): any hardcoded score threshold would have retrieved neither — the top-k doctrine, now with proof.

NDCG@k (eq. 16.25) is the same idea with a finer ruler — graded relevance (0/1/2…) discounted by position. Reach for it when your annotations carry grades; binary gold does not need it.

§4Faithfulness, two moves (eq. 16.26)

faithfulness = claims supported by context / total claims
move 1 — citation integrity (mechanical, deterministic):
        regex /\[Doc (\d+)\]/g over the answer → every N must resolve to a fed doc
        catches: fabricated REFERENCES (failure mode #6's mechanical half)

move 2 — the judge (semantic, live):
        second model call reads context + answer together, enumerates each distinct
        factual claim, verdicts it supported / unsupported BY THE CONTEXT ALONE
        catches: unsupported CLAIMS — incl. the weights leak (failure mode #5:
        "hallucination despite retrieval — model ignores context, answers from
        parametric memory"), i.e. grounding failing at generation time
Judge contract clauseWhy
Strict JSON: {"claims":[{claim, supported}]}Structured output, not prose — the verdict must be machine-usable
zod safeParse at the boundary (strip fences first)The judge's text is untrusted output at your third boundary: wire → seam → judge
Judge enumerates; your code dividesNever let the model do the metric's arithmetic — extraction is its job, the ratio is yours
Judge reads context alone as ground truthFaithfulness measures grounding, not world-truth; a perfectly faithful answer can still be wrong if retrieval fed it lies (that's context poisoning, mode #2)

Faithful ≠ relevant: a refusal (“the context does not contain this”) scores 1.0 — every claim supported — and answers nothing. Answer relevance (eq. 16.27) is the other axis.

§6When to graduate to a framework

RAGAs (book §16.8.3) packages exactly what you hand-rolled — reference-free, LLM-judged faithfulness / answer-relevance / context-precision / context-recall — plus answer correctness against reference answers. Adopt it when the harness's maintenance cost exceeds a dependency's cost: many golden rows, multiple corpora, CI integration. Until then, yours is small, typed, deterministic where it can be, and every line of it is yours. (Currency note: RAGAs' v0.1 API took question/answer/contexts/ground_truth; v0.2+ renamed to user_input/response/retrieved_contexts/reference — the book's listing 16.12 shows the old shape.)
