Lesson 0001 · ~35 minutes · Foundations track

Your Python already knows TypeScript

The one type-system pattern every AI agent in TypeScript rests on — and why your pydantic instincts are about to pay off.

Today's win

You will run your first TypeScript program: a typed agent message dispatcher — the exact skeleton every agent loop is built on. Then you'll break it on purpose and watch the compiler refuse. That refusal is the whole point: in agent code, a message type you forgot to handle is a production incident; in TypeScript it's a red squiggle.

§1Why this is lesson one

Your mission is agents + RAG in TypeScript. The agent ecosystem you're heading into — the MCP TypeScript SDK, the Vercel AI SDK — is written in, and best served by, TypeScript. Meanwhile your textbook (Roitman 2026) teaches those same concepts in Python. So this course runs a permanent translation exercise: concepts from the book's Python, implementations in TypeScript. That makes your ten-thousand hours of Python an asset instead of a tax.

You are not learning a new language from scratch. You are learning a dialect. Typed Python (pydantic, | unions, match) has quietly converged with TypeScript; the syntax moved more than the ideas did. The genuine differences fit in a phrasebook, not a bookshelf.

§2Five mappings, five minutes

Everything below is expanded with copy-paste rows in the Python → TypeScript phrasebook — bookmark it; we'll link back to it whenever a new mapping appears.

1. Type annotations: same colon, no escape hatch

python
name: str = "claude"
top_k: int = 5
# annotations optional, checked
# only if you run mypy/pyright
typescript
const name: string = "claude";
let topK: number = 5;
// types checked always, by the
// compiler — mypy is not optional

Default to const (rebinding forbidden); reach for let only when you must rebind. There is no third option — var is archaeology.

2. Unions: you already speak them

python (3.10+)
def f(x: int | None) -> str | list[str]: ...
Role = Literal["user", "assistant"]
typescript
function f(x: number | null): string | string[] { ... }
type Role = "user" | "assistant";

Identical mental model. Literal becomes a plain union of strings — no import, and it serializes to JSON for free (which is why agent SDKs use it for message roles everywhere).

3. dict[str, Any] → Record<string, unknown>

The Any habit is the one thing you must un-learn. TS has any too — it switches the type system off. The honest type is unknown: "this is something; narrow it before use." Agent code constantly ingests untrusted JSON (model output!), so this discipline is the job.

4. Async: same keywords, no event-loop management

python
results = await asyncio.gather(
    ask("a"), ask("b"),
)
typescript
const results = await Promise.all([
  ask("a"), ask("b"),
]);

asyncio.gather → Promise.all. Coroutine → Promise. There is no asyncio.run — the runtime owns the loop. This mapping is nearly free for you.

5. pydantic erases — so validation is a library

TS interfaces vanish at compile time. For shapes that cross a trust boundary (API responses, tool-call arguments from a model), the TS ecosystem uses zod — the pydantic of TypeScript. z.object({...}).parse(raw) is BaseModel.model_validate(raw). Full side-by-side in the phrasebook §7.

§3The artifact: every agent is a discriminated union

Here is the load-bearing idea of this lesson. An agent conversation is a stream of messages with different shapes: plain text, tool calls, tool results, errors. Every serious TS agent SDK (MCP, Vercel AI SDK, the Anthropic SDK's streaming events) models this the same way: a discriminated union — objects sharing a literal tag field, here called kind. It is your match msg: + isinstance pattern, made compile-time-enforced.

python — the idea, in your dialect
class TextMessage(BaseModel):
    role: Role
    kind: Literal["text"]
    text: str

class ToolCallMessage(BaseModel):
    role: Literal["assistant"]
    kind: Literal["tool_call"]
    tool: str
    args: dict[str, Any]

match msg:
    case ToolCallMessage(tool=t):
        ...
typescript — same idea, enforced
interface TextMessage {
  role: Role;
  kind: "text";        // literal tag
  text: string;
}

interface ToolCallMessage {
  role: "assistant";
  kind: "tool_call";   // literal tag
  tool: string;
  args: Record<string, unknown>;
}

function describe(msg: AgentMessage) {
  switch (msg.kind) {   // narrows!
    case "tool_call": return msg.tool;
  }
}

Inside case "tool_call", TypeScript knows msg is a ToolCallMessage — msg.tool exists, msg.text would be a compile error. That knowledge is called narrowing, and it's why agent code in TS reads so clean: the branching is the typing.

§4The lab — build it, run it, break it

Do this now. Every step is copy-paste; the whole lab fits in one sitting. Work inside this repository, under labs/.

  1. Check Node. Run node -v. You want v20 or later (for fetch and --env-file). If missing: nodejs.org or brew install node.
  2. Scaffold the lab — this step creates the labs/ folder; it doesn't exist until you run this:
    shell — from the repository root (learn-ai-agents/)
    mkdir -p labs/0001-agent-types && cd labs/0001-agent-types
npm init -y
npm install --save-dev typescript tsx @types/node
npx tsc --init   # writes tsconfig.json — strict is on by default
  3. Create agent-types.ts (full file below) in that directory:
    labs/0001-agent-types/agent-types.ts
    // The shapes every agent speaks — and the pattern all agent TS rests on.

type Role = "user" | "assistant";

interface TextMessage {
  role: Role;
  kind: "text";
  text: string;
}

interface ToolCallMessage {
  role: "assistant";
  kind: "tool_call";
  tool: string;
  args: Record<string, unknown>;
}

type AgentMessage = TextMessage | ToolCallMessage;

function describe(msg: AgentMessage): string {
  switch (msg.kind) {
    case "text":
      return `${msg.role} says: ${msg.text}`;
    case "tool_call":
      return `${msg.role} calls ${msg.tool}(${JSON.stringify(msg.args)})`;
  }
}

const conversation: AgentMessage[] = [
  { role: "user", kind: "text", text: "What's in chapter 16 of the guide?" },
  { role: "assistant", kind: "tool_call", tool: "search_docs", args: { query: "chapter 16 RAG" } },
];

for (const msg of conversation) {
  console.log(describe(msg));
}
  4. Run it. npx tsx agent-types.ts — expect exactly:
    expected output
    user says: What's in chapter 16 of the guide?
assistant calls search_docs({"query":"chapter 16 RAG"})
    That's your first TS program: typed, compiled, dispatched on a discriminated union.
  5. Exercise A — extend the union. Add a ToolResultMessage interface (kind: "tool_result", field result: string), add it to AgentMessage, add the case to describe, and append one to conversation. Re-run. Predict the output before you run — then check.
  6. Exercise B — break it (the important one). Comment out the entire case "tool_call": block, then run npx tsc --noEmit (that's your mypy). Read the error: Function lacks ending return statement and return type does not include 'undefined'. The compiler caught an agent that silently drops tool calls. Uncomment, re-check, feel the safety net. Note: tsx runs without checking — tsc --noEmit is the step that types; both commands are your new pytest-adjacent reflex.

Stretch — a real round-trip (optional, needs a key)

If you have an ANTHROPIC_API_KEY, prove the channel is live with zero SDKs. Save as stretch.mts (the .mts extension forces ES modules, which top-level await requires) and run node --env-file=.env stretch.mts — no, npx tsx stretch.mts, since it's TypeScript:

labs/0001-agent-types/stretch.mts
const key = process.env.ANTHROPIC_API_KEY;
if (!key) throw new Error("set ANTHROPIC_API_KEY");   // honest narrowing, no `!`

const res = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "x-api-key": key,
    "anthropic-version": "2023-06-01",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-sonnet-4-5",      // or whatever your Console lists
    max_tokens: 64,
    messages: [{ role: "user", content: "Reply with exactly: agent channel open" }],
  }),
});
const data: unknown = await res.json();  // unknown — we haven't validated it yet
console.log(data);
