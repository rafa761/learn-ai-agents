Read the scores

Today's win

One page of fraction arithmetic, checked by machines. By the end you can compute recall@k, precision@k, MRR and faithfulness by hand — on lesson 0006's real numbers, on a fresh toy golden set, and on the 0.875 itself — and name the denominator of every score before you believe it.

§1One idea under all four metrics

Every score in the harness is the same gesture: count the things that made it, divide by the things you measured against. A fraction. The top of a fraction is called the numerator; the bottom is the denominator. Throughout this lesson the numerator is sienna and the denominator is blue — learn the colors and you will never misread a score again.

MetricThe question it answersNumerator (what made it)Denominator (measured against)
recall@kOf the gold that exists, how much did the top-k window find?gold inside the windowgold existing in total (eq. 16.22)
precision@kOf what you fed the model, how much was gold?gold inside the windowwindow width k (eq. 16.23)

Read that table as the whole lesson in miniature: recall and precision share a numerator and swap denominators; MRR divides by a position; faithfulness divides by a count of claims — never chunks, never citations, never documents. Your quiz miss from 0006 (“a faithfulness of 0.75…”) was not a knowledge gap — it was a denominator swap. The rule to carry out of today: read any score as “x of y” before believing it. If you cannot name y, the number has not told you anything yet.

§2The pictures

Four scenes, one per metric. Chunks are c0–c3; gold chunks (a human marked them relevant) carry a star; the dashed box is the top-k window — what actually reached the model.

Recall — the coverage fraction

rank 1c0 rank 2c1 rank 3c2 rank 4c3

recall@2 = gold inside window: 1gold existing: 2 = 1/2 → 0.50. Look at c2: gold, real, existing — and outside the window. That is recall's unpaid debt, and k=3 would collect it.

Precision — the dilution fraction

rank 1c0 rank 2c1 rank 3c2 rank 4c3

precision@3 = gold inside window: 1window width: 3 = 1/3 → 0.33. Same scene, recall@3 = 1/1 — all the gold that exists was found. Perfect coverage, expensive delivery: two different verdicts, one denominator apart.

The first gold at rank 1 owns the whole podium: 1/1 = 1.00. At rank 2 it earns half — 12 = 0.50; at rank 4, a quarter. Presence says “found eventually”; reciprocal rank says “found early” — and early evidence writes better prompts. MRR is just the mean of these podium shares over the golden set.

Faithfulness — the claims bench

✓ in contextchunk overlap preserves sentences cut at boundaries
✓ in contextwindows in this corpus are 60 words wide
✗ from nowherethe corpus is the entire Hitchhiker's Guide
✓ in contextretrieval scores are cosine similarities

faithfulness = claims supported: 3claims total: 4 = 3/4 → 0.75. The answer is decomposed into claims — atomic little propositions the judge lists — and the ratio runs over claims, never over chunks, citations, or documents. One claim in four traces to nothing you fed the model: your quiz-0006 question, drawn.

§3By hand, on your own 0.875

These are your real numbers — the golden set from lesson 0006's verified run (2026-09-08). Four scored rows; the Vogon negative probe carries no retrieval score. Here is everything you need, and nothing you don't:

Golden rowGold set (annotated by you)Where the golds ranked

Now recall@1, row by row, in pencil. The window is one chunk wide; each row's denominator is its own gold count:

recall@1 = 1+0.5+1+14 rows = 3.5/4 = 0.875

The three single-gold rows each found their one gold at rank 1: 1/1. The straddled row — two golds, window of one — fetched half its evidence: 0.5. The 0.875 was never a mystery: it is “one row could only fetch half its evidence at k=1”, averaged with three perfect rows. Half-of-one-row becomes an eighth off the whole. And note what the number cannot tell you until you decompose it: three rows are already perfect, so no chunker improvement on earth moves them — only the straddled row can, by making its evidence fit one window. That is why harness metrics are means of per-row fractions: the mean hides which row owes the debt.

Pencil, then check: with the same four rows, work out recall@2, precision@2, precision@3 and MRR. Two hints: precision@3's four rows sum to 5/3, so the mean is 5/12 ≈ 0.417; and MRR asks only where each row's first gold sat. Answers in the metrics-by-hand cheat sheet — and §5's machine re-checks the same arithmetic on a toy set.

§4The machines

Two small interactive labs — course components now (assets/metrics.js), bound for the capstone's report page. They exist so you can break things and watch which number moves. The feedback is instant because the readout always names the numerator and the denominator, then the fraction, then the decimal.

Three things to do with the ranking machine (do them in order):

  1. Slide k to 1. Read recall@1 = 1/2 — that single cell is why 0006's whole-harness recall@1 could not have been 1.0: one straddled row.
  2. Back at k=2, click c2 to mark it gold. recall@2 falls to 2/3 while precision@2 stays 2/2. Watch which denominator moved: recall's grew (more gold exists now — c2 sits outside the window); precision's never moves for gold it cannot see.
  3. Clear the golds, then make c3 the only gold. Slide k: recall stays 0.000 until k=4, where it jumps to 1.000 — but precision@4 = 1/4 and 1/rank = 0.25. Deeply buried evidence: found, late, and expensive. This is the “threshold is a bug” doctrine from 0006, now in your hand.

It opens on 0.75 — your number. Toggle the third claim's badge to ✓: 1.00. Toggle two: 0.50 — two leaks in four. The move to notice: badges only ever change the numerator. The denominator moves when the judge's enumeration changes — a claim appearing or disappearing — which is precisely why lesson 0006's discipline is “the judge enumerates, the code divides.” Five claims with one unsupported would read 4/5 = 0.80 — the number §5's lab prints.

Step 1 — type the checker. Short by design — the formulas are one-liners because by now you are the formula:

labs/0007-read-the-metrics/verify.ts
// Lesson 0007 — the fraction reader: your pencil table, machine-checked.
// The rankings below are toys; the arithmetic is the real thing (eq. 16.22–16.26).

type Row = { q: string; ranked: number[]; gold: number[] };

const ROWS: Row[] = [
  { q: "why must consecutive chunks share overlapping words", ranked: [2, 0, 1, 3], gold: [2] },
  { q: "what three limitations come from storing knowledge in weights", ranked: [0, 1, 2, 3], gold: [0, 1] },
  { q: "what does retrieval-augmented generation give to language models", ranked: [1, 0, 2, 3], gold: [0] },
];

const VERDICT: Array<{ claim: string; supported: boolean }> = [
  { claim: "overlap lets a sentence cut at a boundary survive whole in the next chunk", supported: true },
  { claim: "the corpus is the full Hitchhiker's Guide", supported: false },
  { claim: "windows in this corpus are 60 words wide with 12 of overlap", supported: true },
  { claim: "retrieval scores are cosine similarities between query and chunk", supported: true },
  { claim: "k was chosen by metrics, not by taste", supported: true },
];

const hits = (row: Row, k: number): number =>
  row.gold.filter((g) => row.ranked.slice(0, k).includes(g)).length;

const firstGoldRank = (row: Row): number =>
  row.ranked.findIndex((c) => row.gold.includes(c)) + 1;

const mean = (f: (row: Row) => number): number =>
  ROWS.reduce((sum, row) => sum + f(row), 0) / ROWS.length;

console.log("row by row (the pencil table, machine-checked):");
for (const row of ROWS) {
  console.log(`  "${row.q}"`);
  console.log(`    first gold at rank ${firstGoldRank(row)} -> 1/rank = ${(1 / firstGoldRank(row)).toFixed(3)}`);
  for (const k of [1, 2, 3]) {
    console.log(`    k=${k}: recall = ${hits(row, k)}/${row.gold.length}   precision = ${hits(row, k)}/${k}`);
  }
}

console.log("\nharness numbers (mean over the 3 rows):");
for (const k of [1, 2, 3]) {
  console.log(
    `  recall@${k} = ${mean((r) => hits(r, k) / r.gold.length).toFixed(3)}    precision@${k} = ${mean((r) => hits(r, k) / k).toFixed(3)}`,
  );
}
console.log(`  MRR = ${mean((r) => 1 / firstGoldRank(r)).toFixed(3)}`);

const supported = VERDICT.filter((c) => c.supported).length;
console.log(`\nfaithfulness = ${supported}/${VERDICT.length} = ${(supported / VERDICT.length).toFixed(3)} (eq. 16.26)`);
shell — run it (pure arithmetic; no API, no .env needed)
pnpm typecheck
pnpm exec tsx labs/0007-read-the-metrics/verify.ts
