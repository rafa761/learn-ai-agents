Evaluate the loop

You have built RAG end to end and watched it work — twice. But “watched it work” is an anecdote, not evidence. When the capstone works, you will be able to prove it. When it breaks, you will know which half broke.

Today's win

Two files. retrieval.ts — lesson 0004's core, promoted from script to module. evaluate.ts — an offline metrics table (recall@k, precision@k, MRR) over a golden set, then one live judged answer with citation checking. The same harness rides into the capstone unchanged; only the golden set grows.

§1Why evaluation is its own discipline

The book's §16.8 opens with the uncomfortable arithmetic of pipelines: errors can originate at any stage — and they compound. A perfect generator cannot compensate for irrelevant retrievals, and a perfect retriever is wasted if the generator hallucinates or ignores what it was handed. So a RAG system that “feels right” in demos tells you nothing about where its next failure will come from. Evaluation therefore works at levels:

LevelThe question it answersInstrument
1 · Retrieval qualityDid the right passages surface — and how high?Metrics over a golden set, in deterministic code (today, fully)
2 · Generation qualityIs the answer correct, faithful to its context, relevant?Citation check + LLM judge (today: faithfulness)
3 · End-to-end qualityDoes the full system satisfy the user?Human preference, task success — production concerns, named for later

The book's warning is worth pinning to the wall: optimizing only one level backfires. Its example — maximizing recall with a large k fills the context with marginally relevant passages that actively degrade generation. You will watch that happen to your own numbers today, in the precision column. And note the failure mode the book lists under §16.8.4: “hallucination despite retrieval — model ignores retrieved context and generates from parametric memory.” That is your lesson-0005 quiz miss, wearing its production name. Faithfulness is the metric built to catch it.

§2Three ideas, each with a why

1. The golden set — evaluation data is code. A small array of rows: a question, the chunk indices a human judged relevant, and — for questions that deserve no answer — an expectRefusal flag. The annotation is the irreplaceable step: you read the corpus once and mark, for each question, which chunks contain the answer. Judgment, because your chunker cuts mid-sentence by design — today one question's answer genuinely straddles two chunks, and the annotator (you) says so. The negative probe keeps the harness honest: a system can score perfectly on questions that have answers and still fail the user whose question has none. Your Vogon control question is that probe.

2. Three retrieval metrics, one why each (book eq. 16.22–16.24, translated):
recall@k — of the chunks that are relevant, what share made the top-k? With single-gold questions this is hit-rate: found or not. With multi-gold questions it can be 0.5 — half the evidence made it — which is exactly what happens today.
precision@k — of the chunks you fed the model, what share was gold? This is the over-retrieval tax, measured. Every non-gold chunk in the prompt is dilution the book warned about, paid for in tokens.
MRR (mean reciprocal rank) — the average of 1/rank of the first gold chunk. Position, not just presence: gold at rank 1 contributes 1.0, gold at rank 2 contributes 0.5. A retriever that finds the answer eventually and a retriever that finds it first are not the same engine.

3. Faithfulness in two moves (book eq. 16.26: claims supported by context / total claims). The mechanical move is a citation check: extract every [Doc N] from the answer with a regex and verify it resolves to a chunk you actually fed — three lines of deterministic code that catch fabricated references. The semantic move is a judge: a second model call that reads the context and the answer together, enumerates the answer's claims, and verdicts each one supported or not — by the context alone. Then the discipline that makes it trustworthy: the judge enumerates, your code divides. The model never computes the metric's arithmetic; it returns structured verdicts, zod checks them at the boundary (the wire → the seam → the judge: your lesson-0003 doctrine, third deployment), and TypeScript does the ratio.

// Lesson 0004's retrieval core, fourth typing — and its promotion to a MODULE.
// One deliberate interface change from lesson 0005: rank() returns the FULL ranking,
// because evaluation must measure every k — the k you ship is just one slice of it.
// Offline: the embedding model is local — this file never touches the network.

import { pipeline } from "@huggingface/transformers";

const EXCERPT = [
  "Retrieval-Augmented Generation equips large language models with a dynamic, updatable external memory, enabling accurate, grounded, and verifiable responses across knowledge-intensive tasks.",
  "Large language models store knowledge parametrically, compressed into billions of weights during training. This creates three fundamental limitations: hallucination, where models confidently generate plausible but incorrect statements beyond their reliable knowledge boundary; knowledge staleness, because training data has a cutoff date; and domain specificity, since general-purpose models lack deep knowledge of proprietary codebases and documents.",
  "Chunking is the process of splitting documents into segments that are small enough to fit in an embedding model's context window, semantically coherent, and containing enough context to be useful when retrieved in isolation.",
  "The simplest strategy splits every W tokens with an overlap of O tokens between consecutive chunks. Overlap preserves context across boundaries: a sentence cut at a chunk edge still appears whole inside its neighbour chunk, so retrieval never loses a thought merely because a window ended mid-thought.",
].join("\n\n");

function chunkTexts(text: string, size: number, overlap: number): string[] {
  if (overlap >= size) throw new Error(`overlap (${overlap}) must be smaller than size (${size})`);
  const words = text.split(/\s+/).filter(Boolean);
  const step = size - overlap;
  const out: string[] = [];
  for (let start = 0; start < words.length; start += step) {
    const window = words.slice(start, start + size);
    if (window.length === 0) break;
    out.push(window.join(" "));
    if (start + size >= words.length) break;
  }
  return out;
}

function cosine(a: ArrayLike<number>, b: ArrayLike<number>): number {
  let dot = 0;
  let normA = 0;
  let normB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}

const embedder = await pipeline("feature-extraction", "Xenova/all-MiniLM-L6-v2");

async function embed(text: string): Promise<Float32Array> {
  const tensor = await embedder(text, { pooling: "mean", normalize: true });
  return tensor.data as Float32Array;
}

const chunks = chunkTexts(EXCERPT, 60, 12);
const chunkVectors = await Promise.all(chunks.map(embed));

export interface RankedChunk {
  text: string;
  score: number;
  index: number; // position in `chunks` — the identity the golden set refers to
}

/** All chunks for one query, best first. Callers slice their own top-k. */
export async function rank(query: string): Promise<RankedChunk[]> {
  const queryVector = await embed(query);
  return chunks
    .map((text, index) => ({ text, score: cosine(queryVector, chunkVectors[index]), index }))
    .sort((x, y) => y.score - x.score);
}

// The evidence layer: does the loop you built actually work? Numbers, not vibes.
// Book §16.8, translated. Offline half: metrics. Live half: judge (needs the key).

import Anthropic from "@anthropic-ai/sdk";
import { z } from "zod";
import { rank } from "./retrieval.js"; // nodenext: the file is retrieval.TS — import paths say .js

try {
  process.loadEnvFile(".env"); // metrics half works without it; judge half needs the key
} catch {
  // no .env — fine: the offline metrics below still run to completion
}

// ---------- 1. The golden set: evaluation data is code, annotation is the human step ----------

interface GoldRow {
  q: string;
  relevant: number[]; // chunk indices a human judged relevant — by reading the corpus once
  expectRefusal?: true; // negative probe: nothing is relevant; the SYSTEM wins by refusing
}

// Annotated against chunkTexts(EXCERPT, 60, 12) — boundaries verified live:
// the chunker cuts mid-sentence (by design), so annotation is judgment, and judgment is yours.
const GOLDEN: GoldRow[] = [
  { q: "why must consecutive chunks share overlapping words", relevant: [2] },
  { q: "what three limitations come from storing knowledge in weights", relevant: [0, 1] }, // the list straddles both
  { q: "what does chunking do to documents", relevant: [1] },
  { q: "what does retrieval-augmented generation give to language models", relevant: [0] },
  { q: "what do Vogons think of poetry", relevant: [], expectRefusal: true }, // off-corpus control
];

// ---------- 2. Retrieval metrics (book eq. 16.22–16.24, translated) ----------

const rows = await Promise.all(
  GOLDEN.map(async (g) => ({ ...g, ranked: await rank(g.q) })),
);

console.log("=== Level 1 — retrieval quality (deterministic: same corpus, model, cache) ===\n");

for (const row of rows) {
  const top3 = row.ranked.slice(0, 3).map((r) => `${r.index}:${r.score.toFixed(3)}`).join("  ");
  if (row.expectRefusal) {
    console.log(`negative probe: "${row.q}"`);
    console.log(`  top-3: ${top3} — flat; nothing is relevant, and the system wins by refusing\n`);
    continue;
  }
  const positions = row.relevant.map((i) => row.ranked.findIndex((r) => r.index === i) + 1);
  console.log(`"${row.q}"`);
  console.log(`  gold ${row.relevant.join(", ")} at rank(s) ${positions.join(", ")}   top-3: ${top3}\n`);
}

const scored = rows.filter((r) => !r.expectRefusal); // negative probes carry no retrieval score

// recall@k: of the chunks that ARE relevant, what share made the top-k?
const recallAt = (k: number) =>
  scored.reduce((sum, row) => {
    const topK = row.ranked.slice(0, k).map((r) => r.index);
    const hits = row.relevant.filter((i) => topK.includes(i)).length;
    return sum + hits / row.relevant.length;
  }, 0) / scored.length;

// precision@k: of the chunks you fed the model, what share was gold? (the over-retrieval tax)
const precisionAt = (k: number) =>
  scored.reduce((sum, row) => {
    const topK = row.ranked.slice(0, k).map((r) => r.index);
    const hits = row.relevant.filter((i) => topK.includes(i)).length;
    return sum + hits / k;
  }, 0) / scored.length;

// MRR: 1/rank of the FIRST gold chunk, averaged — position is rewarded, not just presence
const mrr =
  scored.reduce((sum, row) => {
    const first = row.ranked.findIndex((r) => row.relevant.includes(r.index)) + 1;
    return sum + 1 / first;
  }, 0) / scored.length;

console.log(`recall@1 = ${recallAt(1).toFixed(3)}    recall@2 = ${recallAt(2).toFixed(3)}    recall@3 = ${recallAt(3).toFixed(3)}`);
console.log(`precision@2 = ${precisionAt(2).toFixed(3)}    precision@3 = ${precisionAt(3).toFixed(3)}`);
console.log(`MRR = ${mrr.toFixed(3)}`);

// ---------- 3. Faithfulness (live): citation check + judge (book eq. 16.26) ----------

const client = process.env.ANTHROPIC_API_KEY ? new Anthropic() : null;

if (!client) {
  console.log("=== Level 2 — skipped: no ANTHROPIC_API_KEY (run with .env present for the judge) ===");
} else {
  console.log("=== Level 2 — generation quality: faithfulness (live) ===");

  const judged = GOLDEN[0]; // the overlap question — the one you eyeballed in lesson 0005
  const docs = (await rank(judged.q)).slice(0, 2); // top-2: recall@2 = 1.00, and precision beats k=3
  const context = docs
    .map((d, i) => `[Doc ${i + 1}] (score ${d.score.toFixed(3)})\n${d.text}`)
    .join("\n\n");

  const answerReply = await client.messages.create({
    model: "claude-haiku-4-5",
    max_tokens: 512,
    system:
      "You are a retrieval-augmented assistant. Answer the question using ONLY the " +
      "provided context documents. If the context does not contain enough information, " +
      "say so explicitly — do not use your own knowledge to fill gaps. Cite your sources " +
      "using [Doc N] notation.",
    messages: [{ role: "user", content: `Context documents:\n\n${context}\n\nQuestion: ${judged.q}` }],
  });
  const answer = answerReply.content
    .filter((b): b is Anthropic.TextBlock => b.type === "text")
    .map((b) => b.text)
    .join("");

  console.log(`question: ${judged.q}`);
  console.log(`answer:\n${answer.trim()}\n`);

  // 3a. citation integrity — the mechanical half, deterministic: every [Doc N] must resolve
  const cited = [...answer.matchAll(/\[Doc (\d+)\]/g)].map((m) => Number(m[1]));
  const dangling = cited.filter((n) => n < 1 || n > docs.length);
  console.log(
    dangling.length === 0
      ? `citation check: ${cited.length} citation(s), all resolve to fed docs — pass`
      : `citation check: FAIL — [Doc ${dangling.join("], [Doc ")}] not among the ${docs.length} fed docs`,
  );

  // 3b. the judge — the semantic half: does each claim trace to the context? (eq. 16.26)
  const judgeReply = await client.messages.create({
    model: "claude-haiku-4-5",
    max_tokens: 1024,
    system:
      'You are an evaluation judge. Given context documents and an answer, enumerate the answer\'s ' +
      "distinct factual claims and decide for each whether the CONTEXT ALONE supports it. Respond with " +
      'ONLY a JSON object of shape {"claims":[{"claim":string,"supported":boolean}]} — no preamble, no trailing prose.',
    messages: [
      { role: "user", content: `Context documents:\n\n${context}\n\nAnswer: ${answer}\n\nEnumerate the claims.` },
    ],
  });
  const judgeText = judgeReply.content
    .filter((b): b is Anthropic.TextBlock => b.type === "text")
    .map((b) => b.text)
    .join("");

  // the judge's text is untrusted output at a new boundary: strip fences, parse, THEN zod —
  // the lesson-0003 doctrine, third boundary (wire → seam → judge)
  const JudgeVerdict = z.object({
    claims: z.array(z.object({ claim: z.string(), supported: z.boolean() })),
  });
  const verdict = JudgeVerdict.safeParse(
    (() => {
      try {
        return JSON.parse(judgeText.replace(/^```(?:json)?\s*/i, "").replace(/\s*```$/, "").trim());
      } catch (e) {
        throw new Error(`judge output is not JSON — got: ${judgeText.slice(0, 200)}`);
      }
    })(),
  );
  if (!verdict.success) throw new Error(`judge output failed its schema: ${verdict.error.message}`);

  // the judge enumerates; YOUR code divides. Never let the model do the metric's arithmetic.
  const claims = verdict.data.claims;
  const supported = claims.filter((c) => c.supported).length;
  for (const c of claims) console.log(`  ${c.supported ? "✓" : "✗"} ${c.claim}`);
  console.log(
    `\nfaithfulness = ${supported}/${claims.length} = ${(supported / claims.length).toFixed(2)} (eq. 16.26)`,
  );
}

§4What you just built

The evidence harness. Three things to carry out of it:

Measurement changed your configuration. Lesson 0005 shipped k=3 on taste; today's numbers say k=2 finds every gold chunk and k=3 only adds dilution — so the judged answer ships k=2. That is the entire profession in one move: defaults are hypotheses; metrics are the verdict. Every capstone change (chunk size, overlap, model, k) now re-runs this file and defends itself with the same table.

The determinism split, again and forever. Level 1 is a pure function — same corpus, model, cache → identical scores across sessions (your 0.541 top hit is the same number lessons 0004 and 0005 printed). The judge is stochastic: re-run it and claim counts may shift by one. So the debugging protocol is ordered by cost and stability: when an answer is wrong, check level 1 first (deterministic, free, instant), and only then suspect level 2. You will use this protocol for the rest of your career.

One metric, one failure mode. Recall drops → the retriever (or the chunker — the straddled gold is your standing example that chunk boundaries shape what is findable). Precision drops → over-retrieval, dilution, cost. Citation check fails → fabricated references, a mechanical bug. Faithfulness drops → the weights leak, failure mode #5, the model ignoring your evidence. Wrong but faithful and well-retrieved → the answer-relevance axis, level 2's other half, waiting in the cheat sheet.
